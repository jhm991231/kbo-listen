# KBO-Listen: 야구 중계를 듣고 볼카운트 맞히기

야구 중계 음성을 듣고, **지금 이 순간의 볼-스트라이크-아웃(B-S-O)**을 맞히는 음성인식 챌린지입니다.

> 아주대학교 Automatic Speech Recognition (2026 가을) 챌린지 과제

- 데이터셋: [hyeonmin1/kbo-listen](https://huggingface.co/datasets/hyeonmin1/kbo-listen) (Hugging Face)
- 홈페이지: https://jhm991231.github.io/kbo-listen/

```
🎙️ "원아웃, 타석에는 김도영. … 바깥으로 살짝 벗어납니다. … 배트가 허공을 가릅니다."
                                                                 ▶ t = 21.4초  →  1볼 1스트라이크 1아웃
```

## 왜 어려운가

받아쓰기만 잘해서는 풀리지 않습니다. 실제 중계처럼

- 캐스터가 판정을 **매번 말하지 않고** (`카운트 투앤원`처럼 가끔 정리해 줄 뿐)
- **"볼", "스트라이크" 같은 단어 없이 묘사로** 전하고 ("바깥으로 흘러 나갑니다", "배트가 허공을 가릅니다")
- 해설위원이 **판정 단어가 들어간 일반론**을 섞습니다 ("풀카운트까지 가면 투수도 부담이 크죠" — 지금 카운트가 아님)

그래서 음성을 정확히 받아쓰는 것(ASR)과 **그 말이 경기 상태를 어떻게 바꾸는지 이해하는 것**이 모두 필요합니다.
베이스라인에서 받아쓰기 오류율(CER)을 12.5% → 3.8%로 줄여도 Hard 트랙 점수는 4점밖에 오르지 않습니다.

## 과제

- **입력**: 반 이닝 분량의 중계 음성(평균 약 97초)과 질의 시각 목록
- **출력**: 각 질의 시각 t에서의 B-S-O (`b` 0–3, `s` 0–2, `o` 0–2, 3아웃 직후는 `o` 3)
- 질의는 판정이 전달된 직후, 다음 발화가 시작되기 전에 놓입니다. 그 시점까지 들은 말만으로 답할 수 있습니다.
- 판정이 생략되어 아직 알 수 없는 구간에는 질의를 두지 않습니다 (뒤에 나오는 카운트 언급으로 확인 가능해진 뒤에만 질의).

## 데이터셋

| split | 시즌 | 클립 (Easy / Hard) | 질의 | 공개 |
|---|---|---|---|---|
| train | 2023 · 2024 · 2025 절반 | 1,000 (500 / 500) | 16,159 | 음성, 질의, 정답, 대본 |
| dev | 2025 나머지 절반 | 100 (50 / 50) | 1,534 | 음성, 질의, 정답 |
| test | 2026 | 200 (100 / 100) | 3,153 | 음성, 질의 (정답 비공개) |

총 **1,300클립, 약 35시간**. 경기 단위로 split을 나눠 같은 경기가 두 split에 걸치지 않습니다.

### 트랙

| | Easy | Hard |
|---|---|---|
| 판정 생략 | 없음 | 생략 가능한 투구의 50% (같은 타석에서 뒤에 카운트 언급이 있는 투구만) |
| 해설위원 | 맞장구·코멘트 | 더 자주 + **방해 코멘트** (판정 단어가 들어간 일반론) |
| 대본 | 템플릿 | **LLM 의역** (판정 단어 없는 묘사가 많음) |
| 드문 이벤트 | 없음 | 절반의 클립 (피치클락 위반, 투구 없는 볼넷, 주루사) |

### 파일 형식

```
{split}/
  audio/{clip_id}.wav      24kHz mono
  queries.json             {"clip_id": [t1, t2, ...]}
  gt.json                  {"clip_id": [{"t": 13.59, "b": 0, "s": 1, "o": 0}, ...]}   (test 제외)
  scripts.jsonl            발화별 텍스트·화자·시작/끝 시각 (train만)
  meta.jsonl               트랙, 태그, 시즌, 목소리 등
```

다운로드: *(공개 준비 중)*

### 만든 방법

실제 중계 음성은 저작권 때문에 배포할 수 없어서, **실제 KBO 경기 기록을 바탕으로 중계를 합성**했습니다.

1. **정답**: KBO 투구 단위 기록([slothman3878/kbo_playbyplay](https://huggingface.co/datasets/slothman3878/kbo_playbyplay), CC BY 4.0)을 반 이닝 클립으로 자르고, 투구마다 B-S-O를 계산 (기록과 재생 결과 불일치 0건)
2. **대본**: 실제 중계 말투를 참고한 템플릿으로 캐스터·해설위원 대본 생성 (`kbolisten/script.py`)
3. **의역 (Hard)**: Qwen3-32B로 판정 발화와 해설을 다시 쓰고, Gemma 3 27B가 원문을 모른 채 판정을 분류해 원래 판정과 같을 때만 채택 (`kbolisten/paraphrase.py`)
4. **음성**: Qwen3-TTS로 설계한 **가상의 목소리**(캐스터 3명, 해설위원 2명)로 합성. 실존 인물의 목소리는 쓰지 않았습니다.

**의역 품질 (사람 블라인드 점검, 100문장)**: 판정 문장의 판정 일치 **97.3%** (73/75), 어색한 표현 13%.
Hard 트랙에는 사람이 들어도 판정이 애매한 발화가 소수 포함될 수 있습니다.

## 평가

주 지표는 **exact**: 질의에서 B, S, O 세 값이 모두 맞은 비율. 빠진 질의는 오답으로 셉니다.
보조 지표로 B, S, O 각각의 정확도와 트랙별 점수를 함께 봅니다.

```bash
python -m kbolisten.evaluate --gt dev/gt.json --pred my_pred.json --meta dev/meta.jsonl
```

예측 파일은 정답 파일과 같은 형식입니다: `{"clip_id": [{"t": 13.59, "b": 0, "s": 1, "o": 0}, ...]}`

## 베이스라인

```
음성 → ASR (단어별 시각) → 키워드 규칙으로 판정 추출 → 상태머신 → 질의 시각별 B-S-O
```

| ASR | CER | exact | Easy | Hard |
|---|---|---|---|---|
| Whisper large-v3 | 12.5% | 71.3% | 81.4% | 61.7% |
| Qwen3-ASR-1.7B + ForcedAligner | 3.8% | **75.0%** | **85.3%** | **65.1%** |

dev + test 300클립, 질의 4,687개 기준. 코드는 `notebooks/08_baseline_rules.ipynb`.

- Qwen3-ASR은 데이터 합성에 쓴 Qwen3-TTS와 같은 계열이라 합성 음성에 유리할 수 있습니다.
- Whisper는 30초 구간 경계에서 글자가 깨지거나 같은 문장을 두 번 받아쓰고, 무음 구간에서 없는 말을 지어내는 경우가 있습니다.

### 참가자용 도구: 상태머신

야구 규칙(4볼 볼넷, 3스트라이크 삼진, 2스트라이크 뒤 파울 등)은 `kbolisten/state_machine.py`가 처리합니다.
음성에서 **무슨 일이 일어났는지**만 알아내 넣으면 B-S-O를 계산해 줍니다. 사용은 자유입니다.

```python
from kbolisten.state_machine import answer_queries

actions = [(12.5, "strike", {}), (14.3, "ball", {}), (17.4, "in_play", {"outs": 1})]
pred = answer_queries(actions, query_times=[13.0, 15.0, 18.0])
```

모든 단계는 Colab 노트북입니다. 시드를 고정해서 같은 클립·대본·목소리 배정이 나옵니다 (TTS 음성과 LLM 의역은 실행마다 조금씩 달라질 수 있어, 배포 데이터 자체를 기준으로 삼습니다).

| 노트북 | 내용 | GPU |
|---|---|---|
| 01 · 02 · 03 | 경기 기록 탐색, 상태머신 검증, 클립별 정답 생성 (`labels_all.jsonl`) | 없음 |
| 04 · 04b | 대본 템플릿, 실제 중계 말투 분석 (원문 자막은 저작권 때문에 저장소에 없음) | 없음 |
| 05 · 05b · 05c | 캐스터·해설위원 목소리 설계 | 아무 GPU |
| 07 | Hard 트랙 LLM 의역 + 검증 + 사람 점검 표본 | A100·G4 (약 1시간) |
| 06 | TTS 합성, 질의·정답 생성 | G4 약 2.5시간 / A100 약 8시간 |
| 08 | 베이스라인 (Whisper, Qwen3-ASR) | 아무 GPU (L4 이상) |

노트북의 `MODE`를 `"pilot"`(20클립, 설계 검증)이나 `"main"`(본 데이터셋)으로 정해 07 → 06 → 08 순서로 실행합니다.
클립 샘플링·트랙 설정은 `kbolisten/build.py`, 노트북은 Google Drive `kbo-listen/` 폴더를 작업 공간으로 씁니다.

### 설계 과정 (파일럿 20클립, Whisper 베이스라인)

| 버전 | 바꾼 것 | Easy | Hard |
|---|---|---|---|
| v1 | 태그로 Hard 정의 | Hard가 오히려 쉬움 | |
| v3 | 판정 생략 + 해설위원 + 방해 코멘트 | 약 80% | 약 72% |

## 저장소 구조

```
kbolisten/
  script.py          경기 기록 → 중계 대본 (템플릿, 해설위원, 판정 생략)
```
