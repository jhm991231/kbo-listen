야구 중계를 듣고,
그 순간의 볼카운트를 맞히는
음성인식 챌린지

반 이닝 분량의 중계 음성과 질의 시각이 주어집니다. 각 시각의 볼·스트라이크·아웃을 답하세요. 캐스터는 판정을 매번 말하지 않고, 해설위원은 판정 단어로 헷갈리게 합니다. 받아쓰기만으로는 풀리지 않습니다.

과제

입력
반 이닝 분량의 중계 음성(평균 약 97초)과 질의 시각 목록
출력
질의 시각 t마다 B(볼 0–3), S(스트라이크 0–2), O(아웃 0–3)
질의 위치
판정이 전해진 직후, 다음 말이 시작되기 전. 판정이 생략돼 아직 알 수 없는 구간에는 질의를 두지 않습니다.

왜 어려운가

  • 판정을 매번 말하지 않습니다실제 중계처럼 캐스터가 판정을 건너뛰고, 가끔 카운트 투앤원처럼 정리해 줍니다. 그 사이는 추론하거나 다음 언급을 기다려야 합니다.
  • 판정 단어 없이 묘사합니다바깥으로 흘러 나갑니다는 볼, 배트가 허공을 가릅니다는 헛스윙, 뒤로 걷어냅니다는 파울입니다. 키워드를 찾는 방식으로는 놓칩니다.
  • 해설이 헷갈리게 합니다풀카운트까지 가면 투수도 부담이 크죠에는 판정 단어가 들리지만, 지금 카운트 얘기가 아닙니다.

베이스라인에서 받아쓰기 오류율(CER)을 12.5%에서 3.8%로 줄여도 Hard 트랙 점수는 3.4점만 오릅니다. 이 챌린지의 병목은 듣기가 아니라 이해입니다.

만든 방법

실제 중계 음성은 저작권 때문에 배포할 수 없어서, 실제 경기 기록을 바탕으로 중계를 합성했습니다.

  1. 정답: KBO 투구 단위 기록(slothman3878/kbo_playbyplay, CC BY 4.0)으로 투구마다 B-S-O를 계산
  2. 대본: 실제 중계 말투를 참고한 템플릿으로 캐스터·해설위원 대본 생성
  3. 의역 (Hard): Qwen3-32B가 다시 쓰고, Gemma 3 27B가 원문을 모른 채 판정을 분류해 원래 판정과 같을 때만 채택
  4. 음성: Qwen3-TTS로 설계한 가상의 캐스터 3명, 해설위원 2명 목소리로 합성. 실존 인물의 목소리는 쓰지 않았습니다.

의역 품질은 사람이 직접 확인했습니다. 원문과 정답을 모른 채 의역 100문장을 판정했을 때 판정 문장의 97.3%(73/75)가 원래 판정과 일치했고, 13%는 표현이 어색했습니다.

파일 형식

{split}/
  audio/{clip_id}.wav     24kHz mono
  queries.json            {"clip_id": [t1, t2, ...]}
  gt.json                 {"clip_id": [{"t": 13.59, "b": 0, "s": 1, "o": 0}, ...]}   test 제외
  scripts.jsonl           발화별 텍스트·화자·시작/끝 시각   train만
  meta.jsonl              트랙, 태그, 시즌, 목소리

평가

주 지표는 exact입니다. 질의에서 B, S, O 세 값이 모두 맞은 비율이며, 답이 없는 질의는 오답으로 셉니다. B, S, O 각각의 정확도와 트랙별 점수를 함께 봅니다.

python -m kbolisten.evaluate --gt dev/gt.json --pred pred.json --meta dev/meta.jsonl

예측 파일은 정답 파일과 같은 형식입니다: {"clip_id": [{"t": 13.59, "b": 0, "s": 1, "o": 0}, ...]}

dev + test 300클립, 질의 4,687개 기준이라 test만 쓰는 리더보드 숫자와 다릅니다. 코드: 08_baseline_rules.ipynb

  • 키워드 규칙은 일부러 단순하게 만들었습니다. 카운트 투앤원, 원아웃, 타석에는 같은 언급이 나오면 상태를 바로잡습니다.
  • Hard에서 틀리는 대부분은 판정 단어가 없는 묘사(뒤쪽으로 걷어냅니다)와 판정 생략입니다.
  • Qwen3-ASR은 합성에 쓴 Qwen3-TTS와 같은 계열이라 합성 음성에 유리할 수 있습니다.
  • Whisper는 30초 구간 경계에서 글자가 깨지거나 같은 문장을 두 번 받아쓰고, 무음 구간에서 없는 말을 지어내기도 합니다.

참가자용 도구: 상태머신

야구 규칙(4볼 볼넷, 3스트라이크 삼진, 2스트라이크 뒤 파울)은 kbolisten/state_machine.py가 처리합니다. 음성에서 무슨 일이 일어났는지만 알아내 넣으면 B-S-O를 계산해 줍니다. 사용은 자유입니다.

from kbolisten.state_machine import answer_queries

actions = [(12.5, "strike", {}), (14.3, "ball", {}), (17.4, "in_play", {"outs": 1})]
pred = answer_queries(actions, query_times=[13.0, 15.0, 18.0])

규칙

질의 시각 t의 답은 t까지 들린 말만 근거로 해야 합니다(온라인 방식). 받아쓰기는 클립 전체에 한 번 돌려도 되지만, t 이후에 끝나는 발화의 내용을 답에 쓰면 안 됩니다. 뒤에 나오는 카운트 언급을 미리 들으면 판정 생략이 의미가 없어지기 때문입니다.

허용

  • 사전학습 모델(ASR, LLM 등)과 외부 데이터. 제출할 때 무엇을 썼는지 적어 주세요.
  • train의 정답·대본(scripts.jsonl)으로 학습, dev로 튜닝
  • 제공된 상태머신을 쓰거나 직접 만드는 것

금지

  • 질의 시각 이후의 발화 내용을 답에 쓰는 것
  • test 음성을 사람이 듣고 라벨을 붙이는 것
  • test 데이터로 학습하는 것

참가 방법

  1. Hugging Face에서 데이터셋을 받습니다.
  2. train과 dev로 방법을 만들고, dev에서 평가 코드로 점수를 확인합니다.
  3. test 질의 전체에 대한 예측 파일 pred.json을 만듭니다.
  4. GitHub 저장소에 제출 이슈를 열고 pred.json과 방법 설명(사용한 모델과 외부 데이터, dev 점수)을 첨부합니다. 비공개 정답으로 채점해서 리더보드에 올립니다.

한계와 출처

  • 합성 음성만 있고 실제 중계 음성 평가는 없습니다. 관중 소음도 없습니다.
  • 목소리 5개가 모든 split에 나옵니다. 처음 듣는 목소리에 대한 일반화는 측정하지 않습니다.
  • 질의 대상은 B-S-O뿐입니다. 점수와 주자는 다루지 않습니다.
