1. 첫 화면

KBO-Listen: 야구 중계를 듣고 볼카운트 맞히기

야구 중계 음성을 듣고, 지금 이 순간의 볼-스트라이크-아웃(B-S-O)을 맞히는 음성인식 챌린지. 잘 받아쓰는 것만으로는 부족하고, 캐스터의 말이 경기 상태를 어떻게 바꾸는지 이해해야 한다.

[버튼] 데이터셋 받기   [버튼] GitHub (평가 코드·베이스라인)   [버튼] 리더보드

반 이닝 클립 1,300개 · 합성 중계 음성 35시간 · 질의 20,846개 · 베이스라인 최고 75.0% (dev+test)

[대표 이미지 자리: 중계 음성 파형 위에 질의 시각과 B-S-O 답이 붙어 있는 그림]

2. 과제 요약

과제

입력: 반 이닝 분량의 중계 음성(평균 약 97초)과 질의 시각 목록.
출력: 각 질의 시각 t에서의 B(볼 0–3), S(스트라이크 0–2), O(아웃 0–3).
질의는 판정이 전해진 직후, 다음 말이 시작되기 전에 놓인다.

[오디오 플레이어 자리: 예시 클립 1개 재생]
시각화자발화질의 → 정답
8.5초캐스터원아웃, 타석에는 김도영.
11.9초캐스터초구, 바깥으로 살짝 벗어납니다.t = 14.4 → 1볼 0스트라이크 1아웃
14.6초해설유인구를 잘 참아냈어요.
18.0초캐스터배트가 허공을 가릅니다.t = 20.1 → 1볼 1스트라이크 1아웃
20.3초해설풀카운트까지 가면 투수도 부담이 크죠.
24.2초캐스터뒤로 걷어냅니다.t = 26.0 → 1볼 2스트라이크 1아웃

설명용으로 꾸민 장면. 실제 데이터는 KBO 경기 기록을 바탕으로 합성.

3. 왜 어려운가

왜 어려운가

  • 판정을 매번 말하지 않는다 — 캐스터가 판정을 건너뛰고 가끔 "카운트 투앤원"처럼 정리한다.
  • 판정 단어 없이 묘사한다 — "바깥으로 흘러 나갑니다"(볼), "배트가 허공을 가릅니다"(헛스윙), "뒤로 걷어냅니다"(파울).
  • 헷갈리게 하는 해설 — "풀카운트까지 가면 투수도 부담이 크죠". 판정 단어가 들리지만 지금 카운트가 아님.

핵심 메시지: 받아쓰기 오류율(CER)을 12.5% → 3.8%로 줄여도 Hard 점수는 3.4점만 오른다. 병목은 듣기가 아니라 이해.

만든 방법

실제 중계 음성은 저작권 때문에 배포할 수 없어 실제 경기 기록을 바탕으로 중계를 합성.

[다이어그램 자리: 경기 기록 → 대본 → (Hard) 의역·검증 → TTS 음성 → 질의·정답]
  1. 정답: KBO 투구 단위 기록(slothman3878/kbo_playbyplay, CC BY 4.0)으로 투구마다 B-S-O 계산
  2. 대본: 실제 중계 말투를 참고한 템플릿으로 캐스터·해설위원 대본 생성
  3. 의역 (Hard): Qwen3-32B가 다시 쓰고, Gemma 3 27B가 원문을 모른 채 판정을 분류해 일치할 때만 채택
  4. 음성: Qwen3-TTS로 설계한 가상의 캐스터 3명·해설위원 2명 목소리 (실존 인물 목소리 없음)

의역 품질 점검: 사람이 원문·정답을 모른 채 의역 100문장을 판정 → 판정 문장 97.3%(73/75) 일치, 어색한 표현 13%.

파일 형식

{split}/
  audio/{clip_id}.wav     24kHz mono
  queries.json            {"clip_id": [t1, t2, ...]}
  gt.json                 {"clip_id": [{"t": 13.59, "b": 0, "s": 1, "o": 0}, ...]}   (test 제외)
  scripts.jsonl           발화별 텍스트·화자·시작/끝 시각 (train만)
  meta.jsonl              트랙, 태그, 시즌, 목소리

5. 평가

평가

주 지표 exact: 질의에서 B, S, O 세 값이 모두 맞은 비율. 답이 없는 질의는 오답. 보조: B, S, O 각각의 정확도, 트랙별 점수.

python -m kbolisten.evaluate --gt dev/gt.json --pred pred.json --meta dev/meta.jsonl

예측 파일 형식은 정답과 같음: {"clip_id": [{"t": 13.59, "b": 0, "s": 1, "o": 0}, ...]}

베이스라인

음성 → ASR (단어별 시각) → 키워드 규칙으로 판정 추출 → 상태머신 → 질의 시각별 B-S-O

dev + test 300클립, 질의 4,687개. 코드: 08_baseline_rules.ipynb

  • 키워드 규칙은 일부러 단순하게. "카운트 투앤원", "원아웃, 타석에는…" 언급으로 상태를 바로잡음.
  • Hard 오답 대부분: 판정 단어 없는 묘사("뒤쪽으로 걷어냅니다")와 판정 생략.
  • Qwen3-ASR은 합성에 쓴 Qwen3-TTS와 같은 계열이라 합성 음성에 유리할 수 있음.
  • Whisper는 30초 구간 경계에서 글자 깨짐·문장 중복, 무음 구간에서 없는 말을 지어냄.
[예시 자리: 베이스라인이 틀린 사례 2~3개 (들은 말 / 뽑은 판정 / 정답)]

참가자용 도구: 상태머신

야구 규칙(4볼 볼넷, 3스트라이크 삼진, 2스트라이크 뒤 파울)은 kbolisten/state_machine.py가 처리. 사용은 자유.

from kbolisten.state_machine import answer_queries

actions = [(12.5, "strike", {}), (14.3, "ball", {}), (17.4, "in_play", {"outs": 1})]
pred = answer_queries(actions, query_times=[13.0, 15.0, 18.0])

8. 규칙

규칙

구분내용
금지온라인 방식: 질의 시각 t의 답은 t까지 들린 말만 근거로 한다. 받아쓰기는 클립 전체에 돌려도 되지만, t 이후에 끝나는 발화의 내용을 답에 쓰면 안 된다. (뒤의 카운트 언급을 미리 들으면 판정 생략이 의미 없어짐)
금지test 음성을 사람이 듣고 라벨을 붙이거나, test 데이터로 학습하는 것
허용사전학습 모델(ASR, LLM 등)과 외부 데이터 사용 — 제출 시 명시
허용train의 정답·대본(scripts.jsonl)으로 학습, dev로 튜닝
허용제공된 상태머신을 쓰거나 직접 만드는 것

9. 참가 방법

참가 방법

  1. Hugging Face에서 데이터셋 받기
  2. train·dev로 방법을 만들고 dev에서 점수 확인
  3. test 질의 전체에 대한 예측 파일(pred.json) 만들기
  4. GitHub 저장소에 이슈를 열고 pred.json과 방법 설명(사용한 모델·외부 데이터, dev 점수) 첨부 → 운영자가 비공개 정답으로 채점해 리더보드에 추가

10. 한계 · 출처

한계

  • 합성 음성만 있고 실제 중계 음성 평가는 없음. 관중 소음 없음.
  • 목소리 5개가 모든 split에 나옴 (처음 듣는 목소리에 대한 일반화는 측정하지 않음).
  • 질의 대상은 B-S-O뿐 (점수·주자는 다루지 않음).
